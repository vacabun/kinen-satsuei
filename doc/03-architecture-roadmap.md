# 記念撮影｜跨平台架构与实施路线

## 1. 平台与代码边界

iOS 首版以 iOS 17 为计划最低版本，使用 SwiftUI、系统照片选择器、VisionKit、Vision/Core Image 和 AVFoundation。macOS 第二阶段继续使用 SwiftUI，并提供桌面布局、文件拖放和相机功能缺失时的导入入口。Android 与 Windows 分别提供各自的文件选择、相机、播放器和系统凭据接口。

| 层 | 路径 | 职责 |
| --- | --- | --- |
| 平台界面 | apps/ios、apps/macos、apps/android、apps/windows | 导航、表单、Markdown 展示、媒体选择与播放 |
| Apple 共用包 | packages/apple | Swift 领域对象、资料库读写、Apple 平台适配 |
| 跨平台业务核心 | packages/core | 优先抽取纯业务验证、归档迁移、收藏聚合及资料库合并 |
| 协议样例 | fixtures/library-v1 | 合成资料库、无附件资料库、冲突与迁移样例 |
| 设计 | doc | 产品交互、资料库协议、路线与验收 |
| 临时数据 | .tmp | 本地扫描样本、实验工具产物和临时仓库 |

首版让纯业务函数独立于 SwiftUI、Apple 媒体框架和 SQLite。iOS 和 macOS 共用 Swift 实现。第三个平台启动前，用已有数据样例对照评估 Rust 核心与各端绑定。首批迁移对象为层级验证、日期统计和三方合并，逐步替换 Swift 内部实现，Swift 包继续提供界面调用接口。Git 传输、凭据、照片和视频管线通过平台接口接入。

## 2. 接口与关键约束

| 接口 | 最小行为 |
| --- | --- |
| LibraryStore | 载入快照、按修订号提交修改、列出关联记录、导出与恢复 |
| AssetStore | 导入文件并计算哈希、读取和验证资产、清理失败的临时导入 |
| MediaProcessor | 获取媒体信息、角点建议、透视矫正、生成缩略图 |
| CollectionStatistics | 按成员与日期范围聚合媒体、生成月份序列和未知日期数量 |
| GitTransport | 获取远端分支、拉取、提交推送、返回结构化错误 |
| CredentialStore | 保存和读取指定远程凭据、管理主机指纹、移除凭据 |

用例层依赖接口，平台对象在应用启动时注入。写入在后台串行执行，UI 只消费快照。处理大图和视频时使用磁盘临时文件和有限并发。缩略图生成可取消，退出详情页即可停止无用工作。

领域层校验允许的上下级组合、禁止循环、多个成员引用去重、旅行起止日顺序与媒体关系有效性。实体删除时在同一事务内更新受影响引用。图像文件的重复导入提示复用已有媒体，但用户仍可保留两条独立媒体记录。时间和时区由平台传入，统计规则可用固定日期样例验证。

## 3. 开发顺序与交付

1. **iOS 离线资料库与首页。** 建立 Xcode 工程和 Apple 共用包，实现导航、文件格式、成员管理和本地原子保存。
2. **媒体与收藏。** 跑通扫描、四角矫正、相册导入、视频预览、成员日期编辑和趋势统计。使用真机验证相机权限、批量导入和签名边界。
3. **手帐与层级。** 实现 Markdown 草稿、预览、媒体引用、独立回忆、Live、跨天旅行及子项移动。补资料库导出和恢复。
4. **Git 同步。** 提前并行验证 iOS SSH 构建可行性。在完成本地事务后接入正式同步，以 GitHub 与一台自托管 Git 服务作为验收目标，覆盖双设备修改、失败重试和恢复。
5. **macOS。** 复用资料库与统计逻辑，适配窗口、键盘、拖拽以及文件导入。验证与 iOS 双向同步。
6. **Android 和 Windows。** 基于已发布的格式和测试样例推进核心复用，分别实现平台 UI、媒体和安全存储。

首版采用单人资料库，可绑定多个自己的设备。共同编辑界面、远程媒体流式播放和 Git LFS 留待后续版本。

## 4. 验收场景

| 场景 | 预期结果 |
| --- | --- |
| 首次离线启动 | 到达首页，添加入口居中，能新建成员、媒体和手帐 |
| 扫描倾斜拍立得 | 可修正边角，保留相纸留白与签名；重新矫正后收藏数保持一致 |
| 扫描与拍摄日期不同 | 拍摄月统计遵循手动日期，入库月使用创建时间 |
| 合影关联多位成员 | 成员页分别计数，全库按媒体 ID 计数 |
| 跨天旅行包含多场 Live | 每场可放照片、视频和合影回忆，可移出成为独立记录 |
| 草稿、重启及导出 | 草稿仍能打开；已发布 Markdown 在资料库中可直接阅读；完整导出能在空库恢复 |
| 更换设备恢复 | 用 GitHub 或自建远程与设备专用 SSH 凭据取回内容，缺失附件明确标识 |
| 双设备修改同一篇手帐 | 可合并的修改保留；重叠修改保留双方，人工选择后完成同步 |
| 推送中断、远端更新或密钥失效 | 本地可继续编辑，保留待同步状态，重试后无重复媒体或丢失条目 |
| 老版资料库升级及新版格式保护 | 迁移后媒体和层级完整；未知更高版本停在可恢复状态 |
