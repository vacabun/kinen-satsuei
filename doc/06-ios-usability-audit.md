# 記念撮影｜iOS 极简上手审查

## 目标与范围

让第一次打开应用的人，在无需说明的情况下保存一张拍立得、写下一段回忆，并知道去哪里找回它们。本次依据现有 iOS 页面、源码和设计文档走查。以下为待验证的设计提案。

## 全局界面规则

- 每个页面突出一个主动作。其余选项放在相关内容旁边，低频功能通过有文字的「更多」或设置进入。
- 保留爱心拍立得 Logo。界面采用黑、白、灰与大面积留白，照片保留原色，成员的两个应援色继续用作小面积标记。
- 同一层内容使用连续纸面，通过字号、间距和细分隔线建立层级。减少外层卡片、厚描边和彩色背景。正文页把最大的可用区域留给内容。
- 需要用户做决定的地方使用可理解的动词，例如「保存拍立得」「插入 3 张照片」。首次使用时的关键按钮同时提供文字与图标，可逆操作提供撤销。
- 展开筛选、调整日期、校正、锁定和同步时，才显示相应控件。返回上一页时保留原位置、筛选和选择。大字模式下保证最后一项能滚到固定按钮或底栏上方。

## P0 · 第一次使用与最常用操作

| 功能 | 当前容易卡住的地方 | 极简改法 |
| --- | --- | --- |
| 首次启动与首页 | 空库时用户需要在首页入口与中央「添加」之间理解各自用途。有数据后近期内容占据主要位置，未完成的事项不一定显眼 | 空库直接给「扫描首张拍立得」，次入口「写一段回忆」。保存后提供「查看照片」或「继续扫」。有资料时首页只放最近回忆、近期媒体和确实需要继续的任务 |
| 底栏与添加面板 | 扫一张、连续扫、相册导入、拍照录像同时出现，首次用户先要判断模式 | 顶层只突出「扫描拍立得」和「从相册导入」；「连续拍」放进扫描界面，普通拍照与录像为次入口。沿用首页、笔记、添加、收藏、设置五个位置 |
| 相机 | 自动／手动、检测状态、快门和批次按钮需要同时理解 | 自动默认开启，手动快门一直可按。保留加粗边框与稳定环，同一时刻只显示一句取景提示。使用一条「连续拍 · 已拍 N 张」状态，拍完点「检查 N 张」 |
| 拍完保存 | 预览、对比、旋转、校正、归属、日期和回忆同时展示，核心字段可能落在首屏之外 | 预览下面紧接「成员或团体」与「拍摄日期」，底部固定「保存」。日期显示可改的默认值。原图对比、旋转和校正收在「调整照片」，回忆用一行入口按需展开 |
| 选择成员或团体 | 找不到名字时，需要退出选择页回到表单再新增 | 选择页先显示最近使用、搜索和「新建」。点名字即选中。新建成员只填姓名，头像和两个应援色可按需展开，两个色位可相同。最近使用提供快捷选择，归属仍由用户确认 |
| 连续扫描与批量归档 | 新手需要理解当前照片、批量填写、所选范围和最后的归档按钮 | 批量页先给照片缩略条与统一归属、日期，预选整批并明确显示影响张数，点任一张后可单独修改。只重拍或重试问题项，成功项留在资料库 |
| 写笔记、保存与草稿 | 空白页和完成按钮对标题的要求可能让用户迟迟无法开始；「返回」和「完成」结果不同 | 直接把第一段作为开始入口。无标题时可建议用正文首句或日期作标题，并让用户在保存前改名。顶部保持「插入」「保存」，草稿状态用「已存草稿」反馈，退出保留内容 |

## P1 · 翻阅、编辑与整理

| 功能 | 极简改法 |
| --- | --- |
| 卡片编辑 | 保留连续纸面。顶部「＋」优先显示文字、照片和视频；标题、列表、引用、行程和 Markdown 放在展开菜单。插入后光标落到新卡片，预览返回保留位置。拖拽柄低调显示，左滑及更多菜单保留锁定和删除。已锁定卡片仍可移动，编辑先解锁，删除需确认 |
| 选择媒体 | 进入即看最近的照片和视频。首屏保留「成员」「时间」筛选入口，日期范围、入库时间和媒体类型进入展开筛选。可组合成员与日期。底栏显示「插入 N 项」或「关联 N 项」，跨筛选保留选择及顺序 |
| 笔记与媒体详情 | 正文中有位置的媒体默认使用「插入照片或视频」，详情中的附件区使用「添加附件」。已有照片可以直接「写回忆」；从详情返回保留原来的列表位置 |
| Live 与旅行 | 先显示日期和内容。旅行详情提供「添加行程」「添加 Live」，Live 提供「添加合影回忆」。从父级创建时继承日期建议和归属，可改为独立记录。层级调整集中在「移动到…」 |
| 收藏与搜索 | 收藏首先展示最近拍立得；成员、团体和日期用紧凑筛选条。支持成员与时间组合、显示生效条件和一键清除。对照片搜索优先呈现缩略图，成员、笔记、媒体保留各自的结果分组 |
| 年度格子与统计 | 总数与年度格子作为默认统计，拍摄／入库口径、年份和月度柱状图折叠在次级控制内。点击格子直接看当天并能清除；保留「按日期查看」作为易操作入口。未知日期单列 |
| 相册导入与普通媒体 | 从媒体选择器回来可先判定类型和批次，不把拍立得的必填项套用到普通照片、合影或视频。允许批量填共同字段、逐张修改。缺失文件显示原因和能执行的下一步 |
| 成员与团体管理 | 成员列表先显示姓名和头像，应援色低调展示。把头像、颜色、别名和归档放进同一成员详情。支持从收藏和选择器回到同一个成员管理入口 |

## P2 · 设置、备份与异常恢复

| 功能 | 极简改法 |
| --- | --- |
| 设置首页 | 首屏显示「当前资料库」「成员与团体」「备份与同步」「反馈」四组。Git 地址、分支、密钥放进备份与同步详情 |
| 首次连接 Git | 日常使用默认只保存本机。启用同步后按「填写仓库 → 配置密钥 → 核对指纹 → 选范围」显示当前步骤。保留手动分支、密钥导入、自建服务器和主机指纹核验。同步范围用能恢复的内容举例 |
| 同步状态与冲突 | 首屏只显示「已同步」「本机有未同步内容」「需要处理」及对应动作。详情说明缺失附件、大小限制、网络或鉴权问题。冲突默认并排展示有差异的字段，再展开完整版本 |
| 导出与恢复 | 「备份到文件夹」与「从备份恢复」用相同术语。恢复先显示资料库名、笔记数、媒体数与缺失项，再明确确认打开哪一个库 |
| 反馈 | 从设置直接进入「报告问题」或「提出建议」。GitHub Issue 预填版本和模板，提交前由用户核对公开内容 |
| 权限、加载与异常 | 只在用户触发对应功能时请求权限。用能继续的选择替代单独的失败弹窗，例如「从相册导入」「重试这张」「继续编辑草稿」。底栏、键盘、底部主按钮都占用布局空间；用小屏、最大字号和 VoiceOver 验证 |

## 建议落地顺序与验收

1. 先做首页空库、添加面板与拍完确认页。初步目标是从首页两次点击进入扫描，拍完选归属后直接保存。在样例新用户测试中，观察是否需要帮助、是否误选拍摄日期或成员。
2. 再把写第一段、插媒体和收藏筛选做成连续闭环。从普通笔记录入到插入照片，检查用户是否知道照片插在哪里，以及保存后如何找回。
3. 最后收拢设置、同步和恢复。用一个已有备份的例子测试用户能否理解恢复内容、缺失项和选择的资料库。
4. 每轮分别用空库、已有少量照片和大资料库验证。记录点击次数、完成时间、错误次数以及返回时丢失的筛选。以首次使用者独立完成为验收条件。

## 拍立得双角度融合原型

使用同一张拍立得的两张照片。先对两张照片应用相同的四角校正，再对齐内容，并尽量保持两次拍摄的曝光一致。原型使用第二张中较暗的实际像素替换第一张的疑似过曝区域，输出独立的 PNG。

```sh
swift tools/cheki-reflection-prototype.swift 第一张.png 补拍.png 融合结果.png
```

此版本用于离线样张验证。对齐是输入前提，App 里的补拍融合入口需要先验证自动配准和错位拒绝。验收时检查人脸、签名、白边、同一位置两张都过曝、拍摄角度差过大等情况。
